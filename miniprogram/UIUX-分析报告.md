# SkateSpot 小程序 · 全量功能盘点与 UI/UE 升级建议

> 基于对 `pages/`、`components/`、`custom-tab-bar/`、`app.*` 全部代码的逐页阅读。
> 结论分三层：功能地图 → 全局问题 → 分页面问题，最后给出 P0/P1/P2 路线图。

---

## 一、功能地图

**产品定位**：滑板场地/店铺发现 + LBS 在场感知 + 打卡社区，原生小程序 + 云开发。

| 模块 | 页面 | 核心功能 |
|---|---|---|
| 发现 | `home` | 城市切换、搜索、地图（可折叠、marker 点选、回到定位）、场地/店铺双实体切换、类型筛选、卡片列表、骨架屏、下拉刷新 |
| 社区 | `discover` | 全站打卡流（最新/热门）、点赞、内嵌评论、图片预览、分页加载 |
| 打卡 | `checkins` | 三项统计（总/连续/本周）、月度签到日历、打卡记录（可删）、累计排行榜（可展开） |
| 我的 | `profile` | 资料编辑（头像/昵称/滑龄）、菜单入口、最近签到、计数徽标 |
| 场地详情 | `venue-detail` | 图片轮播、聚合评分（可评分）、地址标签、实时在场人数+头像、打卡动态、签到弹窗（留言+9图）、报错弹窗、导航、庆祝动画、分享 |
| 店铺详情 | `shop-detail` | 轮播、营业状态、评分、服务/时间/地址/电话、打卡动态、打卡弹窗、拨号、导航、分享 |
| 地点打卡 | `place-checkins` | 单一场地/店铺的完整打卡流 + 评论 |
| 管理 | `admin` | 管理员校验、场地/店铺 CRUD（含地图选点、传图）、建议处理、报错处理 |
| 反馈 | `feedback` | 提交建议（类型+文字+3图）、查看处理进度与官方回复 |
| 报错记录 | `reports` | 我的报错列表 + 官方回复 |

**组件**：`venue-card`、`shop-card`、`comment-box`、自定义 tabBar（4 tab）。
**数据闭环完整**：在线心跳、评分聚合、点赞/评论计数、排行榜、报错-处理-回复，都已打通。

## 二、先说做得好的（保留不动）

1. **设计令牌意识**：`app.wxss` 有完整的语义色/文本层级/兼容变量，注释清晰。
2. **边界态处理细**：定位失败兜底、无数据城市不切、权限引导去设置、空态文案具体。
3. **微动效**：骨架屏流光、卡片错峰入场、签到庆祝 pop、在线脉冲点、评分星缩放。
4. **工程细节**：WXS 解决 WXML 表达式限制、cover-view 兼容原生地图、setData 字段裁剪、懒加载。
5. **微信规范**：chooseAvatar + type=nickname 官方头像昵称方案、报错表单校验+shake。

## 三、全局 UI 问题（跨页面）

### 1. 设计令牌定义了但没人用 ⚠️ 最重要
`app.wxss` 定义了 `--card / --primary / --t1~t5 / --line` 等全套变量，但**所有页面 WXSS 100% 硬编码色值**（`#1E1E23`、`#FF5A36`、`#8C8C94`…）。
- 后果：换主题/加亮色模式要全局替换，且变量与硬编码容易漂移。
- 建议：全量替换为 `var(--card)` 等，并约定"页面 WXSS 不允许出现裸色值"。

### 2. 字号粒度过细
全项目出现 **12 种字号**：20/22/24/25/26/27/28/30/32/34/36/40rpx。25/26/27 之间 1-2rpx 差异肉眼不可辨，只会造成维护混乱。
建议收敛为 6 级字阶：

| 层级 | 字号 | 用途 |
|---|---|---|
| caption | 22rpx | 角标、辅助微标 |
| body-s | 24rpx | 次要说明、时间 |
| body | 28rpx | 正文基准 |
| h3 | 32rpx | 卡片标题 |
| h2 | 36rpx | 弹窗标题 |
| h1 | 40rpx | 详情页名称 |

### 3. 圆角不统一
卡片有 16rpx（feed-card/live/calendar）也有 24rpx（venue-card/profile/menu），弹窗 20rpx，图片格 10/12/16rpx 混用。
建议 token 化：卡片 `24rpx`、内嵌容器 `16rpx`、图片格 `12rpx`、弹窗 `24rpx（顶部）/32rpx（居中卡）`。

### 4. 弹窗模式不统一
- 居中卡片：签到、报错、评分、编辑资料（profile）
- 底部 sheet：admin 表单、feedback 表单

**建议规则**：表单输入类（含 textarea/picker，会弹键盘）一律底部 sheet；轻确认/展示类用居中卡。当前编辑资料、签到、报错都是表单却用居中卡，键盘弹起体验差且遮挡。

### 5. 空态/加载态各写各的
- home 空态：图标+文字；discover：文字+按钮；checkins：纯文字一行；reports/feedback：title+desc。
- 加载：home 有骨架屏，其余全是"加载中..."文字。

建议抽 `empty-state` 和 `skeleton` 公共组件，统一"插画/图标 + 标题 + 副文案 + CTA"结构。

### 6. 三份复制的"打卡动态卡片"
`discover.feed-card`、`venue-detail.checkin-card`、`shop-detail.fcard`、`place-checkins.card` 是同一组件的四套类名四套样式（头像 80/80/68/80rpx、圆角 12/12/10/12…）。庆祝层、评分弹窗、打卡弹窗在两个详情页也各复制一份（且 celebrate 图标一边用 checkCircle 一边用 marker.png）。
建议抽 `checkin-feed-card`、`rate-modal`、`checkin-modal`、`celebrate` 四个公共组件，一处改全局生效。

### 7. 细节不一致清单
- 删除图片按钮：venue-detail 用 SVG × 图标，shop-detail/admin/feedback 用文字"×"字符。
- section 标题：checkins/profile 用"横线—文字—横线"装饰，venue-detail/shop-detail 用纯文字左对齐。
- 轮播指示器：venue-detail 自定义"1/3"左下角，shop-detail 用原生 indicator-dots。
- "查看全部"入口：一边是 chevron 图标，一边是"›"字符。

### 8. 对比度风险点
- `#00D4AA` 绿底 + 白字（详情页"已签到"按钮）：对比度约 1.9:1，不达 WCAG AA。建议绿底配深色字 `#003B30`，或改用 `--primary-50` 底 + `--success` 字描边方案。
- `#6E6E76` on `#1E1E23` 约 2.6:1，只可用于占位符，不建议用于正文提示（当前 photo-add-sub、more、sheet-hint 在用）。
- `sheet-hint` 20rpx 字号过小，低于可读下限，建议 ≥22rpx。

## 四、分页面 UI/UE 问题

### home 首页
| # | 问题 | 建议 |
|---|---|---|
| H1 | marker 需点两次才进详情（第一次选中出 callout），无任何引导 | 首次选中时 callout 加"再点一次进入详情"；或改为点 marker 弹**底部半屏场地速览卡**（大众点评模式），卡上放"查看详情/导航" |
| H2 | 店铺与场地在地图上仅靠"[店铺]"文字前缀区分，视觉廉价 | 店铺用不同形状/颜色的 marker 图标（如方底橙边 vs 圆底） |
| H3 | `venue.distance` 是种子数据的**静态假距离**，定位后也不更新，损害数据可信度 | 拿到定位后用 haversine 计算真实距离，并按距离重排列表 |
| H4 | 定位到无场地数据的城市时静默不切城市：地图显示 A 地、列表还是嘉兴，认知裂缝 | 顶部出现一条"当前城市暂无场地，正在展示嘉兴"的提示条 |
| H5 | 筛选 chips 横向滚动无右缘渐隐，用户不知道能滑 | 加右侧渐变遮罩（mask 渐隐最后一个 chip 的一半） |
| H6 | 地图折叠手柄 40rpx 高，热区偏小、hint 20rpx 看不清 | 手柄加高到 64rpx，hint 改图标（箭头上下）或去掉文字 |
| H7 | 骨架屏 3 行文本与真实卡片结构（含 tags/live 行）不一致 | 骨架按真实卡片结构画 4 行 |
| H8 | 搜索是纯过滤，无历史/热词 | 加最近搜索（本地存储即可） |
| H9 | 顶部无品牌感：城市+搜索之外没有 logo/标语，"SkateSpot"只在导航栏 | header 可加小 logo 或滑板图形符号，强化街头主题识别 |

## 五、UE 流程级问题（跨页面）

1. **新用户冷启动**：首次进入无任何引导，"签到"价值（排行/勋章/在场感知）要进 tab 才知道。建议首页首次进入弹一条轻引导，或签到 tab 顶部加价值说明条。
2. **分享链路**：详情页有 onShareAppMessage，但**首页/发现页没有配置分享**，社区内容（打卡流）恰恰是最值得转发的。建议 discover 卡片加转发，feed 卡片带"来自 SkateSpot"小程序卡片。
3. **签到成功后**：庆祝动画 1.8s → 留在详情页。可以加"查看我的签到日历/分享这次打卡"次级动作，把仪式感转化为传播。
4. **信息架构**：签到页同时装"统计+日历+记录+排行"四块，一屏放不下且无锚点。中期可拆 sub-tab（数据/记录/排行）或把排行挪到发现页。
5. **可访问性**：部分按钮有 aria-label（好），但 venue-card 内"此刻 N 人"、状态标签等无障碍朗读缺失；所有可点区域建议 ≥88rpx 热区。
6. **性能**：home 每次 refresh 全量 setData list+markers；图片统一走 fileID 无压缩参数。建议云存储图片走图片处理参数（如 `?imageMogr2/thumbnail/640x`）控制流量，列表一次 setData 差量更新。

## 六、优先级路线图

### P0 · 体验硬伤（1-2 天）
1. 弹窗模式统一：编辑资料/签到/报错改底部 sheet（键盘体验）。
2. 非管理员隐藏"场地管理"入口；处理"设置"假入口（隐藏或做隐私协议页）。
3. 详情页加收藏；补 discover/home 分享配置。
4. 删除按钮去常驻化（左滑或长按）。
5. marker 二次点击加引导文案。
6. 修复"已签到"绿底白字对比度。

### P1 · 一致性与视觉升级（3-5 天）
1. 全量 CSS 变量替换硬编码色值（一次性脚本 + 人工校验）。
2. 字阶/圆角/间距 token 收敛（12 种字号 → 6 级）。
3. 抽公共组件：打卡动态卡、评分弹窗、签到弹窗、庆祝层、空态、骨架屏。
4. 排行榜前三差异化；统计卡数字排版升级。
5. 店铺详情信息区卡片化+图标行。
6. 底部操作栏重排（收藏加入、报错进 ⋯ 菜单）。
7. 真实距离计算 + 按距离排序。

### P2 · 产品化锦上添花
1. 详情页沉浸式自定义导航栏（视觉升级最大单项）。
2. 点赞动效、卡片入场节奏打磨。
3. 日历切月 + 未来日期置灰。
4. 勋章/等级/连签奖励体系。
5. 搜索历史与热词。
6. 云存储图片压缩参数、差量 setData 性能优化。
7. 发现页"热门"改为服务端加权排序。

---

## 七、一句话总结

功能闭环和数据链路已经超出一般 demo 水准，当前短板不在"缺功能"，而在**一致性**（令牌没落地、组件四套复制、弹窗/空态各写各的）和**关键动线**（收藏缺失、删除易误触、表单弹窗键盘体验）。先做 P0 的六件小事，再做 P1 的组件收敛，视觉质感会有台阶式提升。
