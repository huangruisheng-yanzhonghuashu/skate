## 2. 逐模块诊断（对照设计原则）

### 2.1 头图区 —— 信息层级失衡 【原则 2.1 / 2.4】

| 现状 | 问题 |
|---|---|
| 高度 50vh、min 600rpx | 详情页核心动作是「导航 / 签到」，核心信息是「在哪、多远、有没有人」。头图独占半屏，地址/距离/在场全部跌出首屏，户外扫读要翻页 |
| 渐变衬底 240rpx | 过重，压掉图片下半截 |
| 评分叠在图上可点击 | 与 swiper 滑图手势同区，易误触；评分不是详情页第一优先级 |
| 无图场地 | photos 为空时是一块纯 `#1A1A1E` 死黑，无占位设计 |

### 2.2 签到庆祝层 —— 直接违反「内容克制」 【原则 2.5，P0 硬伤】

现状：`celebrateSub` 输出「再打 N 天解锁『M 日坚持』」（`STREAK_MILESTONES = [3, 7, 30, 100]`）。

**这与设计规范 2.5「无营销式激励文案（如『再打 1 天解锁 xx 徽章』）」逐字冲突，是现存最明确的理念违规。**

其次，彩纸 14 片（1.4–2.3s 下落）+ 卡片 pop 0.45s + 光晕 120rpx + 2.6s 强制停留——超出「微动效 ≤250ms、用完即走」纪律。签到是高频动作，每次都被迫看 2.6 秒庆典，与轻量化相悖。

### 2.3 标签与街头感 —— 态度不足 【原则 2.2】

- tags 全部灰色胶囊（`#26262C` + `#A6A6AD`），无品牌橙。而首页 `venue-card` 已定规则「最多 2 个标签、首标签橙色高亮」——详情页没有延续，同一产品两套标签语言。
- 头图没有任何街头元素（倾斜贴纸、角度标签），观感接近标准本地生活模板，违背「包容但不平庸」。

### 2.4 在场卡 —— 语义正确，面积过度 【原则 2.2】

绿色用于「在场」语义完全正确，但整块卡片绿底 7% + 绿边 18%，是页面里面积最大的彩色块，比品牌橙还抢眼——绿色纪律是「仅限语义点缀」，不是「铺一整张卡」。首页热度胶囊是小面积绿点，详情页应对齐同一克制度。

### 2.5 底部操作栏 —— 低频报错挤占主操作 【原则 2.3】

- 「报错」是低频纠错入口，却与「导航」「签到」并列占 1/4 宽度。核心原则要求签到/导航 1-2 步内完成，主按钮越宽越好按。
- 未签到态是「导航 / 签到(主) / 发打卡(ghost) / 报错」四键，已签到态变三键——键位随状态跳动，肌肉记忆被打断。

### 2.6 弹层形态 —— 不统一 【原则 2.1】

发打卡 = 底部 sheet，报错 = 底部 sheet，评分 = 居中卡片。同页三种弹层两种形态，评分应统一为底部 sheet。

### 2.7 打卡动态 —— 与发现页不同构

详情页打卡卡是自绘一套（80rpx 头像、嵌套灰卡），发现页 feed 卡是另一套。同一「打卡」实体两种视觉，维护成本翻倍。应对齐发现页 feed 卡片规范（媒体九宫格规则已一致，缺的是卡片容器与排版统一）。

### 2.8 运营方行 —— 视觉消失

`op-row` 背景 `#1E1E23` 与父级 info 卡完全相同，嵌在卡里无任何分界，用户根本看不出这是个可点入口。

### 2.9 保留项（不动）

- 底部操作栏主按钮橙色渐变 + 圆角胶囊，品牌感正确。
- 快捷签到 `checkin=1` 直达（2 步内完成），符合操作便捷。
- 签到定位硬校验、`onShow` 刷新、心跳 30 分钟口径，数据纪律正确。
- 返回按钮避让胶囊区（左上），符合导航行规则。

## 4. 修改建议（按优先级）

### P0 —— 理念硬伤，先修

1. **删除徽章激励文案**：`celebrateSub` / `STREAK_MILESTONES` 整体移除；庆祝卡只留「签到成功 + 已连续签到 N 天」。
2. **庆祝层瘦身**：动画总时长 ≤250ms。建议去掉彩纸雨，保留徽章卡（opacity + scale 一次 250ms 内完成），1.2s 自动消失或点击即关，不打断后续「发打卡」引导。

### P1 —— 信息层级重构

3. **头图降高**：50vh → **38vh（约 480rpx）**，渐变衬底 240rpx → 160rpx。目标：首屏内露出「地址 + 距离 + 在场状态」。
4. **名称叠图保留，评分下移**：名称 44rpx 大字保留在图上（街头大字报感）；评分（星 + 分 + N 人评价）移到图下信息卡首行，与「距离 pill」同行——评分和距离都是「决策信息」，放一起，户外一次扫完。点击评分仍弹层，但改底部 sheet。
5. **无图占位**：photos 为空时显示线稿滑板场图标 + 场地名，不用死黑块。

### P2 —— 视觉态度

6. **标签规则对齐首页**：最多展示 3 个，**首标签橙色高亮**（`--primary-50` 底 + `--primary-lt` 字），其余灰色；溢出「+N」。
7. **在场卡收窄**：去绿底绿边，改为 `--card` 底 + **左侧 3rpx 绿色态度线**（呼应 venue-card 橙色态度线），脉冲绿点缩小为点缀。绿色回到「语义点缀」纪律内。
8. **街头元素（克制）**：头图右上可加一枚「热门场地」倾斜贴纸 rotate(-6deg)（仅当热度达阈值时显示，无数据不显示）——一处即可，不堆砌。

### P3 —— 结构与统一

9. **报错挪出操作栏**：移到信息卡右上角「···」或地址行尾部小字入口。底部操作栏固定三键：**导航 128rpx / 签到·发打卡 flex 主键 / 发打卡·已签到 128rpx**，键位不再随状态跳动。
10. **评分弹层改底部 sheet**：与打卡/报错同构（把手 + 标题 + 星排 + 提交）。
11. **打卡卡对齐发现页**：复用 feed 卡片视觉（头像 72rpx、容器、字号阶梯），一处改两边生效。
12. **运营方入口显性化**：独立一行 chip 卡 + 左侧橙色态度线 + 「›」，与信息卡拉开层级。

### P4 —— 细节打磨

13. 返回按钮加 `backdrop-filter: blur(8rpx)`，图片上更精致。
14. 头图计数器 1/N 保留右下，但字号 24rpx → 22rpx 降半级，不抢名称。
15. `shop-detail` 同构复用本规范（星级/标签/操作栏/弹层全部一致）。
